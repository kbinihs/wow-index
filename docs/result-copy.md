# 결과 문구

이 문서는 `npm run copy-doc`으로 코드에서 만듭니다. 문구를 고칠 때는 `src/data/profiles.ts`를 고치고 다시 만드세요.

## 머리 문장

- 예: 새로운 것을 시도하는 일을 가장 많이 선택했고, 그다음은 줄이고 끝내는 일이었습니다.
- 1·2위 차이가 0.5 미만이면 덧붙임: 두 방식의 차이는 크지 않았습니다.
- 다섯 방식 차이가 0.5 미만이면 덧붙임: 다섯 방식이 대체로 고르게 나왔습니다.
- 동점일 때: Prototyper와 Builder의 점수가 같습니다. 둘 중 나와 더 가깝다고 생각하는 쪽을 골라 주세요.

## 주 유형

### Prototyper

| 항목 | 내용 |
|---|---|
| 한 줄 설명 | 새 아이디어를 일단 작게 해 보고, 될 만한지 빨리 가려내는 사람 |
| 중요하게 생각하는 것 | 오래 검토하기보다 먼저 해 보고 반응을 확인하는 것 |
| 강점 | 초안을 빨리 만듭니다.<br>한 문제에 여러 방법을 시도해 봅니다.<br>안 되는 안은 미련 없이 접습니다.<br>새로운 기회를 남보다 먼저 알아봅니다. |
| 잘 맞는 일 | 컨셉노트 쓰기, 새 사업 제안 구상, 시범 사업 설계, 새로운 협력 방식 찾기 |
| 주의할 점 | 아이디어가 문서로만 남고 실제로 해 보지 못한 채 끝날 수 있습니다.<br>내부 사람들의 의견만 듣고 판단할 수 있습니다.<br>끝까지 맡아 마무리한 일이 적어 보일 수 있습니다. |
| NGO에서 기억할 점 | 현장 사업은 한번 시작하면 쉽게 되돌릴 수 없습니다. 새로운 시도는 제안서와 설계 단계에서, 실제 반응을 들어 보며 해야 합니다. |
| 스스로 물어볼 질문 | 최근에 만든 초안 가운데 실제로 반응을 받아 본 것은 몇 개인가요? 다음 단계로 넘어간 것은요? |
| 내 기여를 보여 주는 지표 | 반응을 받아 본 안의 수, 접은 안의 수, 다음 단계로 넘어간 안의 수 |

### Builder

| 항목 | 내용 |
|---|---|
| 한 줄 설명 | 정해진 계획을 예산·일정·절차로 짜서 실제로 굴러가게 만드는 사람 |
| 중요하게 생각하는 것 | 누가, 무엇을, 언제까지 하는지가 분명한 것 |
| 강점 | 일의 순서와 역할을 짜임새 있게 나눕니다.<br>예산·일정·협약을 꼼꼼히 챙깁니다.<br>생길 수 있는 문제와 필요한 승인 절차를 미리 챙깁니다. |
| 잘 맞는 일 | 사업 계획 확정, 예산과 협약 준비, 운영 지침 만들기, 업무 체계 세우기 |
| 주의할 점 | 완벽하게 준비하려다 시작이 늦어질 수 있습니다.<br>충분히 시험해 보지 않은 아이디어를 크게 키울 수 있습니다.<br>다 만든 뒤에도 다른 사람에게 넘기지 못하고 계속 붙잡고 있을 수 있습니다. |
| 스스로 물어볼 질문 | 지금 만드는 체계는 작게라도 시험해 본 아이디어에서 나온 것인가요? 다 만들고 나면 누구에게 넘길 건가요? |
| 내 기여를 보여 주는 지표 | 기한 안에 시작한 사업·체계 수, 첫 실행 일정 준수 여부, 인수인계 완료 여부 |

### Sweeper

| 항목 | 내용 |
|---|---|
| 한 줄 설명 | 효과 없는 일은 줄이거나 끝내고, 복잡한 일은 단순하게 정리하는 사람 |
| 중요하게 생각하는 것 | 꼭 필요한 일에 힘을 모으는 것 |
| 강점 | 복잡한 일을 단순하게 정리합니다.<br>그만둘 일을 과감하게 정합니다.<br>겹치는 일을 잘 찾아냅니다.<br>사업을 끝낼 때도 남길 것을 생각하며 마무리합니다. |
| 잘 맞는 일 | 사업 종료·전환 계획, 보고서·양식·회의 줄이기, 사업 전체 점검 |
| 주의할 점 | 비판만 하는 사람으로 보일 수 있습니다.<br>권한 없이 정리하려다 반발을 살 수 있습니다.<br>새로 만든 것이 없어 기여가 적어 보일 수 있습니다. |
| 늘 함께 있어야 할 사람 | 정리를 결정할 권한이 있는 사람 |
| NGO에서 기억할 점 | 현장 사업을 끝낼 때는 지역 주민과 참여자에게 피해가 가지 않도록 끝내는 과정까지 미리 계획해야 합니다. |
| 스스로 물어볼 질문 | 정리를 결정할 권한은 누구에게 있나요? 줄이고 난 빈자리는 무엇으로 채울 건가요? |
| 내 기여를 보여 주는 지표 | 줄인 시간과 비용, 종료·전환을 마친 사업 수, 사업이 끝난 뒤에도 이어지는 변화 |

### Grower

| 항목 | 내용 |
|---|---|
| 한 줄 설명 | 진행 중인 일의 반응과 결과를 보고 조금씩 고쳐 나가는 사람 |
| 중요하게 생각하는 것 | 이미 시작한 일이 받는 사람에게 실제로 도움이 되는지 |
| 강점 | 반응과 결과 자료를 잘 읽어 냅니다.<br>작은 개선을 빠르게 여러 번 해 봅니다.<br>참여자와 후원자의 입장을 잘 헤아립니다. |
| 잘 맞는 일 | 참여율 높이기, 결과 분석, 진행 중인 사업의 성과 높이기, 후원자·파트너 의견 반영 |
| 주의할 점 | 작은 개선에만 매달릴 수 있습니다.<br>처음부터 다시 짜야 할 때도 조금씩 고치는 데 그칠 수 있습니다. |
| NGO에서 기억할 점 | 반응이 나타나는 속도는 대상마다 다릅니다. 후원자 반응은 몇 주 안에 보이지만 현장의 변화는 몇 년이 걸리기도 합니다. 목표를 이루면 참여가 끝나는 사업이라면, 다시 참여하는 사람이 많은 것이 성공의 기준은 아닙니다. |
| 스스로 물어볼 질문 | 지금 고치고 있는 것이 조금 손보는 것으로 충분한가요, 아니면 처음부터 다시 짜야 하나요? |
| 내 기여를 보여 주는 지표 | 개선 전후의 결과, 참여 유지율, 의견을 반영한 건수 |

### Maintainer

| 항목 | 내용 |
|---|---|
| 한 줄 설명 | 이미 돌아가는 일을 기준과 마감에 맞춰 믿을 수 있게 지키는 사람 |
| 중요하게 생각하는 것 | 기준과 마감을 지켜 사람들이 믿고 맡길 수 있게 하는 것 |
| 강점 | 맡은 일을 믿을 수 있게 해냅니다.<br>같은 일을 꾸준하고 정확하게 합니다.<br>문제가 생길 낌새를 일찍 알아챕니다.<br>정해진 기준을 잘 지킵니다. |
| 잘 맞는 일 | 정기 보고, 규정 준수 점검, 장기 사업 관리, 파트너 관계 유지 |
| 주의할 점 | 바꿔야 할 때도 하던 방식을 고집할 수 있습니다.<br>일이 쌓여도 줄이지 못할 수 있습니다.<br>꾸준히 해 온 기여가 잘 드러나지 않을 수 있습니다. |
| 스스로 물어볼 질문 | 지금 지키고 있는 일 가운데 이제 줄여도 되는 것은 무엇인가요? 내가 하는 일이 다른 사람에게 보이고 있나요? |
| 내 기여를 보여 주는 지표 | 마감을 지킨 비율, 사고·감사 지적 건수, 파트너 만족도 |

## 주 유형-보조 유형

| 조합 | 이렇게 일합니다 | 주의할 점 |
|---|---|---|
| Prototyper-Builder | 새 아이디어를 내는 데서 그치지 않고, 실제 사업이 될 때까지 직접 끌고 갑니다. | 처음부터 끝까지 혼자 다 맡으려다 일이 몰릴 수 있습니다. |
| Prototyper-Sweeper | 새로운 것을 해 보고, 안 되는 것은 빨리 접습니다. 일이 쓸데없이 늘어나지 않게 합니다. | 접는 속도가 빨라, 조금 더 지켜볼 만한 일도 일찍 정리할 수 있습니다. |
| Prototyper-Grower | 일단 해 보고, 반응을 보고, 고칩니다. 이 과정을 빠르게 되풀이합니다. | 계속 고치다 보니 한 가지로 정해 굳히는 때가 늦어질 수 있습니다. |
| Prototyper-Maintainer | 새로 해 본 것 가운데 쓸 만한 것은 안정적으로 돌아가도록 챙깁니다. | 새로 벌이는 일과 지켜야 할 일이 함께 늘어 지치기 쉽습니다. |
| Builder-Prototyper | 체계를 만들되, 크게 벌이기 전에 작게 시험해 보고 고릅니다. | 시험과 체계 만들기를 혼자 다 하면 둘 중 하나가 늦어질 수 있습니다. |
| Builder-Sweeper | 체계를 세우고, 불필요한 절차는 덜어 냅니다. | 새 아이디어나 현장의 반응을 놓칠 수 있습니다. |
| Builder-Grower | 체계를 세우고, 그 위에서 사업을 키워 갑니다. | 키우는 데 집중하다 멈추거나 방향을 바꿀 때를 늦게 알아챌 수 있습니다. |
| Builder-Maintainer | 만든 체계가 흔들리지 않게 끝까지 지킵니다. 조직이 안정적으로 돌아가게 하는 힘이 됩니다. | 변화가 필요할 때 움직임이 느릴 수 있습니다. |
| Sweeper-Prototyper | 효과 없는 일을 정리하고, 비운 자리를 새로운 시도로 채웁니다. | 정리와 시도가 빠르게 이어져, 오래 운영해 본 결과가 적게 남을 수 있습니다. |
| Sweeper-Builder | 복잡해진 일을 걷어 내고, 남은 일을 단순한 체계로 다시 세웁니다. | 다시 세우는 데 힘을 쏟다 보면, 정리한 뒤의 반응을 늦게 확인할 수 있습니다. |
| Sweeper-Grower | 중요한 것만 남기고, 남긴 일의 성과를 끌어올립니다. | 결과가 늦게 나타나는 일을 너무 일찍 접을 수 있습니다. |
| Sweeper-Maintainer | 돌아가는 일에서 불필요한 부분을 덜어 내며 지켜 갑니다. | 무엇을 덜어 낼지 기준이 분명하지 않으면, 그 일을 해 온 사람들의 반발을 살 수 있습니다. |
| Grower-Prototyper | 진행 중인 일을 고치다가, 고치는 것만으로 부족하면 새로운 방법을 시험합니다. | 개선과 새 시도가 섞여, 무엇이 효과가 있었는지 가려내기 어려울 수 있습니다. |
| Grower-Builder | 반응을 보며 일을 키우고, 커진 일을 감당할 체계를 만듭니다. | 일이 커지는 만큼 절차도 계속 늘어날 수 있습니다. |
| Grower-Sweeper | 반응이 좋은 일은 키우고, 효과가 적은 일은 줄입니다. | 숫자로 빨리 드러나는 결과만 보고 판단할 수 있습니다. |
| Grower-Maintainer | 후원자·파트너와의 관계를 넓히고 오래 이어 갑니다. | 지금의 관계를 지키는 데 힘을 쏟다 보면, 관계를 새로 짜거나 정리할 때를 놓칠 수 있습니다. |
| Maintainer-Prototyper | 하던 일을 안정적으로 지키면서, 그 안에서 작은 개선을 시도합니다. | 지키는 일과 새로 해 보는 일 사이에서 지치기 쉽습니다. |
| Maintainer-Builder | 돌아가는 일을 지키면서, 흔들리는 부분은 절차와 체계로 단단히 다집니다. | 절차가 늘어나 일이 무거워질 수 있습니다. |
| Maintainer-Sweeper | 돌아가는 일을 단순하고 안정적으로 유지합니다. | 새로운 시도가 줄어들 수 있습니다. |
| Maintainer-Grower | 맡은 일을 지키면서, 반응을 살펴 조금씩 나아지게 합니다. | 작은 개선이 쌓여도 다른 사람 눈에 잘 띄지 않을 수 있습니다. |

## 성장 방향 (3위)

세 번째로 많이 선택한 방식입니다. 어느 정도 익숙한 쪽이라 다음으로 넓혀 보기 좋습니다.

| 3위 | 문장 |
|---|---|
| Prototyper | 하던 일에 작은 시도를 하나씩 더해 보면, 바꿔야 할 때를 놓치지 않게 됩니다. |
| Builder | 해 본 일 가운데 잘된 것을 예산·일정·절차로 정리해 두면, 그 일이 더 크게 이어집니다. |
| Sweeper | 하던 일 가운데 이제 그만해도 되는 것을 골라내면, 꼭 필요한 일에 쓸 힘이 생깁니다. |
| Grower | 끝난 일의 반응과 결과를 한 번 더 살펴보면, 다음에 같은 일을 더 잘하게 됩니다. |
| Maintainer | 만든 것을 다른 사람도 이어 갈 수 있게 기준과 주기를 정해 두면, 결과가 오래 남습니다. |

## 필요한 짝 (4·5위)

가장 적게 선택한 방식입니다. 이 일을 잘하는 사람과 함께하면 내가 놓치기 쉬운 부분을 채울 수 있습니다.

짝이 없을 때: 이번 응답에서는 특별히 적게 선택한 방식이 없었습니다.

| 주 유형 ↓ / 짝 → | Prototyper | Builder | Sweeper | Grower | Maintainer |
|---|---|---|---|---|---|
| Prototyper | — | 좋은 아이디어를 실제 사업으로 만들어 줍니다. | 벌여 놓은 일 가운데 그만둘 것을 정리해 줍니다. | 시작한 일의 반응을 보고 계속 고쳐 줍니다. | 자리 잡은 일을 넘겨받아 꾸준히 지켜 줍니다. |
| Builder | 체계로 만들 만한 새 아이디어를 가져다줍니다. | — | 늘어난 절차와 군더더기를 덜어 줍니다. | 만든 체계가 잘 쓰이는지 보고 고쳐 줍니다. | 완성된 체계를 넘겨받아 지켜 줍니다. |
| Sweeper | 정리하고 비운 자리를 새로운 일로 채워 줍니다. | 정리하고 남은 일을 체계로 다시 세워 줍니다. | — | 남긴 일이 더 나아지도록 반응을 보고 고쳐 줍니다. | 정리한 뒤 남은 일을 꾸준히 지켜 줍니다. |
| Grower | 고치는 것으로 부족할 때 새로운 방법을 찾아 줍니다. | 커진 일을 감당할 체계를 만들어 줍니다. | 효과가 적은 일을 정리해 줍니다. | — | 개선한 결과가 흐트러지지 않게 지켜 줍니다. |
| Maintainer | 바꿔야 할 때를 알려 주고 새 방법을 가져다줍니다. | 흔들리는 부분을 체계로 다시 잡아 줍니다. | 쌓인 일과 군더더기를 덜어 줍니다. | 하던 일이 더 나아지도록 반응을 보고 고쳐 줍니다. | — |
