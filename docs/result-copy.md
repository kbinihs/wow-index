# 결과 문구

이 문서는 `npm run copy-doc`으로 코드에서 만듭니다. 문구를 고칠 때는 `src/data/profiles.ts`를 고치고 다시 만드세요.

## 머리 문장

- 예: 새 아이디어를 내고 만들어 보는 일을 가장 많이 선택했고, 그다음은 다듬고 덜어 내는 일이었습니다.
- 1·2위 차이가 0.5 미만이면 덧붙임: 두 방식의 차이는 크지 않았습니다.
- 다섯 방식 차이가 0.5 미만이면 덧붙임: 다섯 방식이 대체로 고르게 나왔습니다.
- 동점일 때: Prototyper와 Builder의 점수가 같습니다. 둘 중 나와 더 가깝다고 생각하는 쪽을 골라 주세요.

## 주 유형

### Prototyper

| 항목 | 내용 |
|---|---|
| 한 줄 설명 | 새 아이디어를 많이 내고, 빠르게 만들어 보는 사람 |
| 중요하게 생각하는 것 | 많이 시도하는 것. 내놓은 아이디어 대부분이 실제 사업이 되지 않아도 괜찮다고 여깁니다. |
| 강점 | 한 문제에 서로 다른 아이디어를 여러 개 냅니다.<br>아이디어를 초안이나 작은 시범으로 빨리 만들어 봅니다.<br>아무도 해 보지 않은 방식을 먼저 떠올립니다.<br>안 되는 안은 미련 없이 접고 다음 안으로 넘어갑니다. |
| 잘 맞는 일 | 새 사업 구상, 컨셉노트 쓰기, 시범 사업 설계, 새로운 협력 방식 찾기 |
| 주의할 점 | 아이디어가 머릿속이나 문서로만 남고 실제로 만들어 보지 못한 채 끝날 수 있습니다.<br>벌여 놓은 아이디어가 많아 주변 사람이 따라가기 어려울 수 있습니다.<br>끝까지 맡아 마무리한 일이 적어 보일 수 있습니다. |
| NGO에서 기억할 점 | 현장 사업은 한번 시작하면 되돌리기 어렵습니다. 그래서 NGO에서 만들어 보는 단계는 컨셉노트, 작은 시범, 파트너 설명회처럼 되돌릴 수 있는 형태일 때가 많습니다. |
| 스스로 물어볼 질문 | 최근에 낸 아이디어 가운데 실제로 만들어 반응을 받아 본 것은 몇 개인가요? |
| 내 기여를 보여 주는 지표 | 낸 아이디어 수, 만들어 반응을 받아 본 안의 수, 접은 안의 수, 다음 단계로 넘어간 안의 수 |

### Builder

| 항목 | 내용 |
|---|---|
| 한 줄 설명 | 아이디어를 실제로 굴러가는 사업으로 빠르게 만들어 내는 사람 |
| 중요하게 생각하는 것 | 시범으로 된 것을 실제 현장에서 믿고 쓸 수 있는 수준으로 빨리 만드는 것 |
| 강점 | 시범 단계의 아이디어를 정식 사업으로 빠르게 옮깁니다.<br>예산·인력·협약을 갖춰 일을 실제로 시작하게 만듭니다.<br>임시로 돌아가던 방식을 누가 맡아도 돌아가는 체계로 만듭니다. |
| 잘 맞는 일 | 시범 사업을 본사업으로 키우기, 새 사업 출범 준비, 운영 지침과 업무 체계 만들기, 새 시스템 도입 |
| 주의할 점 | 완벽하게 준비하려다 시작이 늦어질 수 있습니다.<br>충분히 시험해 보지 않은 아이디어를 크게 키울 수 있습니다.<br>다 만든 뒤에도 다른 사람에게 넘기지 못하고 계속 붙잡고 있을 수 있습니다. |
| 스스로 물어볼 질문 | 지금 만드는 사업은 작게라도 해 본 아이디어에서 나온 것인가요? 다 만들고 나면 누가 이어받나요? |
| 내 기여를 보여 주는 지표 | 시범에서 정식 사업이 되기까지 걸린 시간, 기한 안에 시작한 사업·체계 수, 시작한 뒤 큰 문제 없이 돌아간 기간 |

### Sweeper

| 항목 | 내용 |
|---|---|
| 한 줄 설명 | 만들어진 일을 다듬고 단순하게 하며, 필요 없는 것은 걷어 내는 사람 |
| 중요하게 생각하는 것 | 사업이 어느 단계에 있든 군더더기를 덜어 내, 꼭 필요한 것만 가볍고 빠르게 돌아가게 하는 것 |
| 강점 | 복잡해진 절차와 자료를 단순하게 정리합니다.<br>그만둘 일을 과감하게 골라냅니다.<br>사람들이 보는 안내문과 양식을 알기 쉽게 다듬습니다.<br>오래 걸리는 과정을 찾아 빠르게 만듭니다. |
| 잘 맞는 일 | 보고서·양식·회의 줄이기, 안내문·신청 절차 다듬기, 겹치는 활동 합치기, 처리 시간 줄이기, 효과 없는 활동 그만두기 |
| 주의할 점 | 비판만 하는 사람으로 보일 수 있습니다.<br>권한 없이 정리하려다 반발을 살 수 있습니다.<br>새로 만든 것이 없어 기여가 적어 보일 수 있습니다. |
| 늘 함께 있어야 할 사람 | 정리를 결정할 권한이 있는 사람 |
| NGO에서 기억할 점 | 현장 활동을 그만두면 참여자와 지역 주민이 영향을 받습니다. 그래서 NGO에서 덜어 내는 일은 내부 절차·양식·회의처럼 바깥에 미치는 영향이 적은 것부터 시작할 때가 많습니다. |
| 스스로 물어볼 질문 | 정리를 결정할 권한은 누구에게 있나요? 덜어 낸 뒤 무엇이 쉬워지고 빨라졌는지 보여 줄 수 있나요? |
| 내 기여를 보여 주는 지표 | 줄인 시간과 비용, 없앤 양식·회의·절차 수, 처리 시간이 줄어든 정도 |

### Grower

| 항목 | 내용 |
|---|---|
| 한 줄 설명 | 시작한 사업을 반응을 보며 고쳐, 참여자와 후원자에게 더 잘 맞게 키우는 사람 |
| 중요하게 생각하는 것 | 만든 것이 받는 사람에게 실제로 필요하고 잘 맞는지 |
| 강점 | 반응과 결과 자료를 잘 읽어 냅니다.<br>작은 개선을 빠르게 여러 번 해 봅니다.<br>사람들이 다시 찾거나 계속 참여하는 이유를 찾아냅니다.<br>참여자와 후원자의 입장을 잘 헤아립니다. |
| 잘 맞는 일 | 참여율 높이기, 결과 분석, 진행 중인 사업의 성과 높이기, 후원자·파트너 의견 반영 |
| 주의할 점 | 작은 개선에만 매달릴 수 있습니다.<br>처음부터 다시 짜야 할 때도 조금씩 고치는 데 그칠 수 있습니다. |
| NGO에서 기억할 점 | 반응이 나타나는 속도는 대상마다 다릅니다. 후원자 반응은 몇 주 안에 보이지만 현장의 변화는 몇 년이 걸리기도 합니다. 목표를 이루면 참여가 끝나는 사업이라면, 다시 참여하는 사람이 많은 것이 성공의 기준은 아닙니다. |
| 스스로 물어볼 질문 | 지금 고치고 있는 것이 조금 손보는 것으로 충분한가요, 아니면 처음부터 다시 짜야 하나요? |
| 내 기여를 보여 주는 지표 | 개선 전후의 결과, 참여 유지율, 의견을 반영한 건수 |

### Maintainer

| 항목 | 내용 |
|---|---|
| 한 줄 설명 | 자리 잡은 사업과 체계를 맡아, 커져도 안전하고 멈추지 않게 지키는 사람 |
| 중요하게 생각하는 것 | 오래 운영하는 사업이 안전하고, 믿을 수 있고, 커져도 효율적으로 돌아가는 것 |
| 강점 | 자리 잡은 사업이나 체계를 책임지고 맡습니다.<br>문제가 생길 낌새를 일찍 알아챕니다.<br>개인정보·회계·안전 기준의 빈틈을 찾아 막습니다.<br>규모가 커져도 비용과 시간이 늘지 않게 운영을 손봅니다. |
| 잘 맞는 일 | 장기 사업 운영, 후원자·참여자 정보 관리, 회계·규정 준수 점검, 운영 시스템 관리, 위험 관리 |
| 주의할 점 | 바꿔야 할 때도 하던 방식을 고집할 수 있습니다.<br>안정을 지키려다 새로운 시도를 막는 사람으로 보일 수 있습니다.<br>문제가 없을 때는 기여가 잘 드러나지 않습니다. |
| 스스로 물어볼 질문 | 지금 맡은 사업이나 체계는 두 배로 커져도 버틸 수 있나요? 내가 막은 문제가 다른 사람에게 보이고 있나요? |
| 내 기여를 보여 주는 지표 | 사고나 중단 없이 운영한 기간, 감사·점검 지적 건수, 규모 대비 운영 비용과 처리 시간 |

## 주 유형-보조 유형

| 조합 | 이렇게 일합니다 | 주의할 점 |
|---|---|---|
| Prototyper-Builder | 새 아이디어를 내는 데서 그치지 않고, 실제 사업이 될 때까지 직접 만들어 냅니다. | 처음부터 끝까지 혼자 다 맡으려다 일이 몰릴 수 있습니다. |
| Prototyper-Sweeper | 많이 만들어 보고, 안 되는 것은 빨리 걷어 냅니다. 일이 쓸데없이 늘어나지 않게 합니다. | 걷어 내는 속도가 빨라, 조금 더 지켜볼 만한 것도 일찍 접을 수 있습니다. |
| Prototyper-Grower | 일단 만들어 보고, 반응을 보고, 고칩니다. 이 과정을 빠르게 되풀이합니다. | 계속 고치다 보니 한 가지로 정해 굳히는 때가 늦어질 수 있습니다. |
| Prototyper-Maintainer | 사업의 시작과 오래 운영하는 단계를 함께 봅니다. 새로 해 본 것 가운데 자리 잡은 것은 튼튼하게 지킵니다. | 새로 벌이는 일과 지켜야 할 일이 함께 늘어 지치기 쉽습니다. |
| Builder-Prototyper | 직접 만들어 본 아이디어 가운데 될 만한 것을 골라 빠르게 실제 사업으로 만듭니다. | 시험과 사업 만들기를 혼자 다 하면 둘 중 하나가 늦어질 수 있습니다. |
| Builder-Sweeper | 사업을 빠르게 세우고, 세운 뒤에는 군더더기를 덜어 내 단단하게 다듬습니다. | 새 아이디어나 참여자의 반응을 놓칠 수 있습니다. |
| Builder-Grower | 사업을 세우고, 반응을 보며 더 잘 맞게 키워 갑니다. | 키우는 데 집중하다 멈추거나 방향을 바꿀 때를 늦게 알아챌 수 있습니다. |
| Builder-Maintainer | 만든 체계가 커져도 흔들리지 않게 끝까지 책임집니다. 조직이 안정적으로 돌아가게 하는 힘이 됩니다. | 변화가 필요할 때 움직임이 느릴 수 있습니다. |
| Sweeper-Prototyper | 군더더기를 걷어 내고, 비운 자리에서 새로운 것을 시도합니다. | 정리와 시도가 빠르게 이어져, 오래 운영해 본 결과가 적게 남을 수 있습니다. |
| Sweeper-Builder | 복잡해진 일을 걷어 내고, 남은 일을 단순하고 단단한 체계로 다시 세웁니다. | 다시 세우는 데 힘을 쏟다 보면, 정리한 뒤의 반응을 늦게 확인할 수 있습니다. |
| Sweeper-Grower | 군더더기를 덜어 내고, 남긴 일이 참여자에게 더 잘 맞도록 키웁니다. | 결과가 늦게 나타나는 일을 너무 일찍 접을 수 있습니다. |
| Sweeper-Maintainer | 자리 잡은 일에서 불필요한 부분을 덜어 내, 더 가볍고 빠르게 돌아가게 합니다. | 무엇을 덜어 낼지 기준이 분명하지 않으면, 그 일을 해 온 사람들의 반발을 살 수 있습니다. |
| Grower-Prototyper | 진행 중인 사업을 키우다가, 고치는 것만으로 부족하면 새로운 방법을 시험합니다. | 개선과 새 시도가 섞여, 무엇이 효과가 있었는지 가려내기 어려울 수 있습니다. |
| Grower-Builder | 반응을 보며 사업을 키우고, 커진 사업을 감당할 체계를 만듭니다. | 일이 커지는 만큼 절차도 계속 늘어날 수 있습니다. |
| Grower-Sweeper | 반응이 좋은 것은 키우고, 효과가 적은 것은 덜어 냅니다. | 숫자로 빨리 드러나는 결과만 보고 판단할 수 있습니다. |
| Grower-Maintainer | 사업을 참여자와 후원자에게 맞게 키우고, 자리 잡은 뒤에도 흔들리지 않게 지킵니다. | 지금의 방식을 지키는 데 힘을 쏟다 보면, 크게 바꿔야 할 때를 놓칠 수 있습니다. |
| Maintainer-Prototyper | 사업의 시작과 오래 운영하는 단계를 함께 봅니다. 자리 잡은 일을 지키면서, 그 안에서 새로운 방법을 시험해 봅니다. | 지키는 일과 새로 해 보는 일 사이에서 지치기 쉽습니다. |
| Maintainer-Builder | 자리 잡은 일을 지키면서, 흔들리는 부분은 체계를 다시 세워 단단히 다집니다. | 절차가 늘어나 일이 무거워질 수 있습니다. |
| Maintainer-Sweeper | 자리 잡은 일을 단순하고 가볍게 유지해, 커져도 빠르고 효율적으로 돌아가게 합니다. | 새로운 시도가 줄어들 수 있습니다. |
| Maintainer-Grower | 자리 잡은 일을 지키면서, 반응을 살펴 조금씩 나아지게 합니다. | 작은 개선이 쌓여도 다른 사람 눈에 잘 띄지 않을 수 있습니다. |

## 성장 방향 (3위)

세 번째로 많이 선택한 방식입니다. 어느 정도 익숙한 쪽이라 다음으로 넓혀 보기 좋습니다.

| 3위 | 문장 |
|---|---|
| Prototyper | 하던 일에 새 아이디어를 몇 개 더 내서 작게 만들어 보면, 바꿔야 할 때를 놓치지 않게 됩니다. |
| Builder | 해 본 일 가운데 될 만한 것을 실제로 굴러가는 형태로 만들어 보면, 아이디어가 사업으로 이어집니다. |
| Sweeper | 하던 일 가운데 덜어 낼 것을 골라내면, 남은 일이 더 단순하고 빨라집니다. |
| Grower | 진행 중인 일의 반응과 결과를 한 번 더 살펴보면, 받는 사람에게 더 잘 맞게 만들 수 있습니다. |
| Maintainer | 맡은 일이 커져도 버틸 수 있게 점검 기준과 주기를 정해 두면, 결과가 오래 남습니다. |

## 필요한 짝 (4·5위)

가장 적게 선택한 방식입니다. 이 일을 잘하는 사람과 함께하면 내가 놓치기 쉬운 부분을 채울 수 있습니다.

짝이 없을 때: 이번 응답에서는 특별히 적게 선택한 방식이 없었습니다.
