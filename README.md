# WoW Index

다섯 가지 업무 방식(Prototyper·Builder·Sweeper·Grower·Maintainer) 가운데 내가 주로 선택하는 두 가지를 주 유형·보조 유형으로 보여 주는 성찰 도구입니다. 서버 없이 브라우저 안에서만 동작하는 단일 HTML 앱입니다.

## 실행

```bash
npm install
npm run dev        # 개발 서버
npm test           # 단위 테스트
npm run build      # dist/index.html(응답 화면), dist/admin.html(관리 화면)을 각각 한 파일로 빌드
npx playwright install chromium   # e2e를 처음 돌리기 전에 한 번
npm run e2e        # 빌드 결과를 브라우저로 끝까지 진행해 보는 검사(Playwright)
npm run contrast   # 색 대비 검사
npm run copy-doc   # 결과 문구 문서(docs/result-copy.md) 다시 만들기
```

## 화면

응답 화면과 관리 화면은 서로 다른 파일입니다. 응답 화면에는 관리 화면으로 가는 링크가 없고, 파일럿 분석 코드도 들어 있지 않습니다. 팀 화면은 팀마다 직접 쓸 수 있게 두 화면 모두에 있습니다.

**응답 화면** `/` (dist/index.html) — 누구나

| 주소 | 화면 |
|---|---|
| `#/` | 처음 화면 |
| `#/test` | 질문(업무 선호 20문항 + 상황 선택 6개) |
| `#/result/<코드>` | 결과(내 결과, 받은 결과) |
| `#/team` | 우리 팀 구성(팀 코드 모아 보기, 사업 단계별 조합 비교) |
| `#/t/<팀 이름>` | 팀 링크. 이 브라우저에 팀 이름을 기억하고 처음 화면으로 갑니다. 결과를 공유할 때 결과 코드에 팀 이름이 붙습니다. |
| `#/pilot` | 파일럿 참여 링크. 이 브라우저에 참여 표시를 켜고 처음 화면으로 갑니다. 켜진 브라우저에서만 결과 화면에 '파일럿 응답 파일 내보내기'가 보입니다. |
| `#/export` | 파일럿 응답 파일 내보내기 |

**관리 화면** `/admin` (dist/admin.html) — 진행자

| 주소 | 화면 |
|---|---|
| `#/` | 관리 화면(팀 화면·분석으로 가는 링크, 파일럿 참여 링크 복사) |
| `#/team` | 우리 팀 구성(팀 코드 모아 보기, 사업 단계별 조합 비교) |
| `#/analysis` | 파일럿 응답 분석(크론바흐 알파, 문항-나머지 상관, 업무 선호와 상황 선택의 1위 일치, 상황 선택이 주 유형을 바꾼 참여자 수, CSV) |

관리 화면은 숨긴 것이지 잠근 것이 아닙니다. 주소를 아는 사람은 열 수 있습니다. 다만 저장된 응답이 없고, 붙여 넣거나 불러온 내용은 그 브라우저에서만 처리하므로 열어도 남의 데이터를 볼 수는 없습니다.

## 팀 결과 모으기

서버 없이 팀원 결과를 모읍니다. 결과는 팀원이 직접 보낸 것만 모이고, 어디에도 저장되지 않습니다.

1. 팀장이 처음 화면(또는 관리 화면)의 작은 버튼 '팀 링크 만들기'를 눌러 팀 이름을 적고, 만들어진 링크를 팀 대화방에 보냅니다.
2. 팀원은 그 링크로 시작해 답합니다. 결과 화면의 팀 이름 칸이 미리 채워져 있습니다.
3. 팀원이 결과 화면에서 '팀 대화방에 보내기'를 누릅니다. 휴대폰은 공유 창이 열리고, 공유 창이 없으면 보낼 내용을 복사합니다.
4. 팀장은 대화방 내용을 통째로 복사해 팀 화면에 붙여 넣거나, 카카오톡 '대화 내보내기' 파일을 올립니다.

팀 화면이 읽는 규칙은 아래와 같습니다.

- 코드가 없는 줄(인사말, 이름, 시각)은 건너뜁니다. 코드처럼 보이는데 읽지 못한 줄만 알립니다.
- 같은 팀·같은 별명으로 여러 번 보냈으면 마지막 것만 씁니다.
- 여러 팀의 코드가 섞여 있으면 팀을 골라 봅니다. 처음에는 이 브라우저에서 팀 링크를 만든 팀, 없으면 팀 링크로 들어온 팀을 보여 줍니다.
- 팀원 이름을 누르면 그 사람의 결과가 새 창으로 열립니다. 그래서 처음 화면에는 코드를 넣어 결과를 여는 칸을 따로 두지 않습니다.

팀 이름은 별명처럼 결과 코드에 붙는 선택 항목이라 코드 버전을 올리지 않았습니다. 팀 이름이 없는 코드도 그대로 열립니다.

## 계산 방법

1. 다섯 방식마다 합산 점수를 냅니다. 업무 선호(A) 문항 4개의 합계(4–20점)에서 시작해, 상황 선택(B) 여섯 상황에서 그 방식을 '가장 맡고 싶음'으로 고를 때마다 1점을 더하고 '가장 맡고 싶지 않음'으로 고를 때마다 1점을 뺍니다(−2–26점).
2. 합산 점수가 높은 순서로 주 유형, 보조 유형, 성장 방향, 채워 줄 짝이 정해집니다. 합산 점수가 같으면 문항 합계가 높은 쪽이, 그것도 같으면 '가장 맡고 싶음'을 더 많이 고른 쪽이 앞섭니다. 그래도 같으면 응답한 사람이 직접 고릅니다.
3. 주 유형과 보조 유형의 합산 점수 차이가 2점 미만이면 두 방식의 차이가 크지 않다는 문장을, 다섯 방식의 최고·최저 차이가 2점 미만이면 고르게 나왔다는 문장을 결과에 덧붙입니다.

결과 화면의 '한눈에 보기'에서 '점수 보기'를 열면 방식별 점수를 볼 수 있습니다. 계산은 `src/scoring.ts`에 있습니다.

## 버전

문항·상황·응답 척도 문구나 계산 방법을 바꾸면 아래 세 값을 함께 올릴지 정합니다. 올리지 않으면 문구나 계산이 다른 응답이 같은 코드·파일로 섞입니다.

- `src/codec.ts`의 `CODE_VERSION`(팀 코드·결과 링크 형식): 현재 6. v6에서 상황 선택을 합산 점수에 넣었습니다. 코드 모양은 v5와 같지만 결과가 달라질 수 있어 v5 이하 코드는 열지 않습니다.
- `src/progress.ts`의 `KEY`(이 브라우저에 저장된 진행 기록): 현재 `wa:progress:v6`. 기록 안의 `v`는 저장 형식 버전이라 문구나 계산이 바뀌어도 그대로 둡니다.
- `src/pilot.ts`의 `PILOT_VERSION`(파일럿 응답 파일): 현재 4

이전 버전 코드는 열 때 '이전 버전에서 만든 코드' 안내가 나오고, 이전 버전 파일럿 파일은 분석 화면에서 따로 세어 뺍니다.

## 배포(Vercel)

`vercel.json`에 설치·빌드 명령(`npm ci`, `npm run build`), 결과 폴더(`dist`), 확장자 없는 주소(`/admin`), 보안 헤더, 검색 노출 막기(`noindex`)가 들어 있습니다.

- GitHub 저장소를 Vercel에서 Import하면 이후 push할 때마다 자동으로 배포됩니다.
- 또는 내 컴퓨터에서: `npx vercel deploy dist --prod`

배포 주소는 링크를 아는 사람 누구나 열 수 있습니다. 응답은 서버로 가지 않고 각자의 브라우저에만 남습니다.
